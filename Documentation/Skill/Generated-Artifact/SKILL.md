# Generated Artifact

A committed artifact is the output of a program, and the program keeps changing.
The file and the program are two statements of one truth.

## The invariant

**Every committed artifact equals what its producer writes today.**

## The failure it prevents

A model gains a field; the schema file does not. Nothing fails, because the file
is valid - it is simply older than the code that reads it. The consumer of the
schema then rejects a field the writer sends, or accepts one that no longer
exists, and the error surfaces at the boundary rather than at the commit that
caused it.

The same failure with a different symptom: an artifact regenerated by hand with a
different tool version, so a formatting change and a content change arrive in one
diff and nobody can separate them.

## The probe

The only honest test is to run the producer and look at what changed. Timestamps
prove nothing; a file can be newer than its producer and still wrong.

Capture the artifact, run the producer, compare, then put it back:

```sh
shasum -a 256 <artifact> > /tmp/before
<producer> --write
shasum -a 256 <artifact> | diff /tmp/before -
```

A non-empty diff is drift. Restore the committed bytes afterwards unless the run
was meant to regenerate them.

Most generators carry the comparison themselves, which is better than wrapping
one: a compare mode that exits non-zero on drift, and a flag that regenerates.

Prefer that form. A producer with a regenerate flag and a compare-by-default mode
is a guard; a producer that only writes is a build step that happens to overwrite
a tracked file.

## The repair

Regenerate, then read the diff before committing it. A regenerated artifact whose
diff contains only the change you made is the expected outcome; one whose diff
contains reordered keys or reformatted output is a producer change that arrived
unnoticed, and it belongs in its own commit.

```sh
<producer> --write
git diff --stat -- <artifacts>
```

## Pitfalls

- **A producer that rewrites unconditionally makes every check a drift report.**
  If it cannot compare, wrap it: snapshot, run, compare, restore.
- **A producer run in the wrong directory writes to the wrong place, or fails
  silently.** State the working directory; a script that resolves paths relative
  to its own file is not the same as one that resolves them relative to the
  caller.
- **A build-directory copy is not a committed artifact.** Regenerating into a
  gitignored output directory proves the producer runs, not that the committed
  file is current. Check the tracked path.
- **A generator that imports through a bundler alias fails when run by bare
  Node.** The alias resolves in the page build and not in the script, which makes
  the guard report drift that is really a resolution failure. Import by the real
  path.
- **A producer that exits 0 while writing nothing looks like agreement.** Compare
  the artifact's digest before and after, not the exit code. A missing artifact
  after a successful run is drift.

## Claim-to-test

| Claim | Probe | Pass condition |
| --- | --- | --- |
| The artifact is current | the producer in compare mode | exit 0 |
| The producer actually writes it | run with `--write`, then `ls -l <artifact>` | mtime advanced, digest matches a second run |
| Regeneration is stable | run `--write` twice, digest after each | identical digests |
| Only intended content changed | `git diff -- <artifacts>` | the diff is the change that was made |
